# Запуск индексации и рекламы

## Что уже есть

9 содержательных страниц для поиска; отдельные коммерческие страницы для эндуро, эвакуатора и лимузинов; ещё 3 страницы под конкретные задачи; сохранён раздел дорожных мотоциклов. Вся информация доступна в исходном HTML без JavaScript.

Уникальные метаданные и H1, canonical, хлебные крошки, структурированные данные, sitemap, robots, Open Graph, адаптивность, локальные шрифты/фотографии, WebP и srcset, отсутствие загрузочного экрана, приоритет загрузки главного изображения, ленивые фотографии ниже первого экрана, доступные элементы и обычные ссылки между страницами.

Техническая готовность не гарантирует ни включение всех страниц в индекс, ни рост позиций за два месяца. Дальнейший результат зависит от домена, спроса, конкуренции, полезности контента, реальных упоминаний, отзывов и работы с обращениями.

## Почему просмотр не индексируется

Пока `site.config.json` содержит `indexable: false`, все страницы получают `noindex,follow`. Так промежуточная копия на GitHub Pages не конкурирует с действующим 3030.by. Это не запрет обхода: robots.txt остаётся доступным и разрешает роботу прочитать метатеги.

Конечный домен не назначен пользователем. CNAME, DNS и перенаправления старого сайта не менялись.

## Перед открытием основного сайта

1. Подтвердите конечный адрес. Если сайт заменяет 3030.by, сохраните этот домен; он уже связан с бизнесом. Если выбран иной адрес, подготовьте отдельный план переноса. Не переносите домен только ради названия ключевого запроса.
2. Уточните конфликтующие цены лимузинов и условия допуска к эндуро в `CONTENT-SOURCES.md`. Проверьте телефон, мессенджеры и наличие техники.
3. В `site.config.json` установите фактический `site_url` без завершающего `/`, например `https://3030.by`, и `indexable: true`.
4. Добавьте реальные коды подтверждения Google и Яндекса в `google_verification` и `yandex_verification`, если используется подтверждение метатегом. Доступные на старом хостинге verification-файлы нужно сохранить при переносе. Никаких выдуманных кодов не добавлено.
5. Пересоберите сайт и проверьте:

```bash
python3 scripts/build.py
python3 scripts/build.py --check
python3 scripts/check.py --production
```

6. Опубликуйте и сохраните сборку в Git. Рабочая конфигурация должна быть в `site.config.json`, чтобы CI проверял тот же адрес. Переменные `SITE_URL` и `INDEXABLE` предназначены также для изолированных тестовых сборок, но не заменяют сохранённые настройки.
7. Проверьте HTTPS и фактические HTTP-ответы: существующие страницы — 200, неизвестные — 404. Не настраивайте общий SPA fallback на главную страницу для всех адресов.
8. Проверьте, что на основных страницах нет `noindex`, `X-Robots-Tag: noindex`, пароля, запрета обхода или сетевой блокировки Googlebot/Яндекса. Проверка проекта не может проверить ещё не подключённый боевой хостинг.

Если GitHub Pages используется как постоянный основной адрес без собственного домена, оставьте в `site_url` полный путь `https://yaroslavkiri4ykknifhit-max.github.io/vadim` и включите `indexable: true`. Решение об основном зеркале всё равно нужно принять, чтобы не оставлять два независимых одинаковых сайта.

## Сохранение адресов при замене старого сайта

| Старый адрес | Новый канонический адрес |
| --- | --- |
| `/` | `/` |
| `/enduro` | `/enduro/` |
| `/evacuator` | `/evacuator/` |
| `/limuzin` | `/limuzin/` |
| `/arenda-moto` | `/arenda-moto/` |
| `/contacts` | `/contacts/` |

Имена разделов сохранены. Статический хостинг должен выдавать один постоянный 301/308 с адреса без завершающего `/` на адрес папки. Для прежних технических Tilda URL и любых иных индексируемых страниц соберите список в Search Console/Вебмастере и настройте соответствие по смыслу. Не переводите все старые URL на главную. Если меняется домен, старые страницы должны перенаправляться на точные новые аналоги. В проекте нет автоматического редиректа на старый домен.

На основном домене нормализуйте HTTP → HTTPS и www → выбранное зеркало средствами хостинга. Редиректы и DNS нельзя подтвердить до подключения домена. Для `/index.html` предпочтителен постоянный редирект на `/`; на Pages canonical уже указывает нужный вариант.

## Google и Яндекс

- Подтвердите основной сайт в Google Search Console и Яндекс Вебмастере.
- Добавьте фактический `https://ВАШ-ДОМЕН/sitemap.xml` и проверьте ответ 200. Карта содержит только канонические коммерческие/контактные страницы; 404 и текст об обработке данных исключены.
- Проверьте главную, эндуро, эвакуатор и лимузины через инструменты проверки URL/переобхода. Отправка sitemap не гарантирует индексацию.
- Проверьте микроразметку. Рейтинги и отзывы не выдуманы; FAQ оставлен как полезный контент без обещания расширенного сниппета.
- Укажите реальный регион в Вебмастере и поддерживайте корректные карточки бизнеса в доступных местных справочниках. Адреса и контакт должны совпадать.
- После запуска смотрите исключения из индекса, ошибки обхода, поисковые запросы, CTR и обращения. Добавляйте реальные фотографии, уточняйте ответы и обновляйте цены.

`lastmod` управляется полем `updated` в `site.config.json`: меняйте его при содержательных правках. Значения `priority` и фиктивная ежедневная `changefreq` не добавлены. В рабочей сборке для Яндекса добавлена директива Clean-param для распространённых рекламных меток; canonical не включает query string.

## Платная реклама и измерения

Направляйте объявление сразу на соответствующую страницу:

- Прокат эндуро → `/enduro/`.
- Первое катание с инструктором → `/enduro/s-instruktorom/`.
- Прокат эндуро на день → `/enduro/na-den/`.
- Эвакуатор → `/evacuator/`.
- Манипулятор → `/evacuator/manipulyator/`.
- Лимузин → `/limuzin/`.

Скрипты счётчиков не добавлены, потому что их реальные идентификаторы не предоставлены. До рекламы установите предоставленные владельцем теги GA/Google Ads/Яндекс Метрики в общий шаблон, при необходимости предусмотрите управление согласием и обновите описание обработки данных. Впишите ID Метрики в `metrika_id`. Одно заполненное поле ID без скрипта Метрики не загружает счётчик.

События:

| Событие | Значение |
| --- | --- |
| `phone_click` | Нажатие на телефон, не подтверждённый звонок |
| `booking_open` | Открытие окна обращения |
| `messenger_click` | Переход по прямой ссылке мессенджера |
| `messenger_open` | Подготовленное сообщение открыто в мессенджере; отправку подтверждает пользователь |
| `price_period` | Переключение будни/выходные |

Персональные данные формы не передаются в события. UTM и click ID остаются в адресе посадочной страницы для подключённого счётчика; сайт не добавляет их в сообщения и не хранит персональные данные в браузере. Для подтверждённых звонков/заявок нужны данные владельца, коллтрекинг или отдельная серверная интеграция; их нельзя заменять количеством кликов.

## Проверки

`scripts/check.py` проверяет HTML, единственный H1, уникальность метаданных, JSON-LD, canonical, sitemap, локальные ссылки, якоря, изображения и шрифты. `--production` дополнительно проверяет снятие noindex с основных страниц. CI повторяет сборку, проверки и синтаксис JavaScript.

Браузерные проверки выполнялись отдельно на ширинах 320, 390, 768 и 1440 px. Проверялись меню, клавиатурное закрытие, тарифы, выбранная услуга/модель в обращении, ссылки WhatsApp/Telegram без реальной отправки, FAQ, галерея и работа без JavaScript. Результаты — в `QA.md`.
